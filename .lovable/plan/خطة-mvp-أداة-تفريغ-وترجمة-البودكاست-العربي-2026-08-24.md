# خطة MVP: أداة تفريغ وترجمة البودكاست العربي

منتج SaaS يرفع فيه المستخدم ملفاً صوتياً أو رابط حلقة، فيحصل على نص عربي منقّح (مع دعم اللهجات) + ترجمة إنجليزية، وتصدير SRT/VTT/TXT، مع اشتراك بسيط.

ملاحظة عن المنصة: الطلب يذكر Next.js + FastAPI. هذا المشروع على Lovable يعمل بـ TanStack Start (React + Vite) مع Lovable Cloud (Postgres + تخزين + وظائف خادم) وبوابة Lovable AI للتفريغ والترجمة. الخطة أدناه مكتوبة بالمعمارية المنطقية، مع عمود «المقابل داخل Lovable» في القسم التقني حتى تكون قابلة للتنفيذ فوراً هنا أو خارجه.

## 1) نطاق MVP

داخل النطاق:
- تسجيل دخول بالبريد/كلمة المرور.
- رفع ملف صوتي (mp3/m4a/wav) حتى 200MB، أو لصق رابط RSS/حلقة مباشر (mp3 URL).
- تفريغ عربي تلقائي مع طوابع زمنية على مستوى المقطع.
- اختيار اللهجة (فصحى، خليجي، مصري، شامي، مغربي) كتلميح للنموذج + مرحلة تنقيح نصي (ترقيم، إزالة الحشو، تصحيح الأسماء).
- ترجمة إنجليزية مطابقة للمقاطع الزمنية.
- محرر نص بسيط: تعديل مقطع، دمج/تقسيم، حفظ.
- تصدير SRT / VTT / TXT (عربي، إنجليزي، أو ثنائي اللغة).
- اشتراك بسيط: مجاني (30 دقيقة/شهر)، احترافي (600 دقيقة/شهر) عبر Stripe.
- لوحة حلقات: الحالة (في الانتظار/معالجة/جاهز/فشل)، الدقائق المستهلكة.

خارج النطاق (لاحقاً):
- فصل المتحدثين (diarization) وتسمية المتحدثين.
- توليد فيديو أو حرق ترجمة على الصوت/الفيديو.
- تعاون متعدد المستخدمين وتعليقات.
- لغات إضافية غير العربية↔الإنجليزية.
- تطبيق موبايل، API عام للعملاء، فرق/فواتير مؤسسية.
- سحب تلقائي دوري من RSS (يدوي فقط في MVP).

## 2) المعمارية التقنية

```text
[Web App]  رفع/متابعة/محرر/تصدير
    |
    v
[API / Server Functions]  auth, quota, jobs, exports
    |            \
    |             -> [Object Storage]  الصوت الأصلي + الصوت المحوَّل
    v
[PostgreSQL]  users, episodes, transcripts, translations, subscriptions
    |
    v
[Worker غير متزامن]
    1. تنزيل/تحويل الصوت (ffmpeg -> 16kHz mono wav، تقطيع 10 دقائق)
    2. STT عربي (Whisper / gpt-4o-transcribe)
    3. تنقيح عربي حسب اللهجة (LLM)
    4. ترجمة إنجليزية مقطعاً بمقطع (LLM)
    5. كتابة النتائج + تحديث الحالة
```

| المكوّن | الطلب الأصلي | المقابل داخل Lovable |
| --- | --- | --- |
| الواجهة | Next.js | TanStack Start (React + Tailwind) |
| API | FastAPI | server functions + `src/routes/api/public/*` للـ webhooks |
| قاعدة البيانات | PostgreSQL | Lovable Cloud (Postgres + RLS) |
| التخزين | S3/مؤقت | Lovable Cloud Storage، حذف الصوت بعد 7 أيام |
| الذكاء | Whisper + Llama | Lovable AI Gateway: `openai/gpt-4o-transcribe` + نموذج نصي للتنقيح/الترجمة |
| الطابور | Celery/RQ | جدول `jobs` + endpoint عامل يُستدعى بـ cron، مع قفل تفاؤلي |
| المدفوعات | Stripe | Stripe عبر تكامل Lovable |

قواعد ثابتة: مفاتيح الذكاء تبقى على الخادم فقط؛ الصوت لا يمر عبر المتصفح إلى مزود الذكاء؛ كل مقطع صوتي يُرسل كملف WAV كامل (لا شظايا).

## 3) مراحل التنفيذ

المرحلة 1 — الأساس والحساب
- تفعيل الـ backend، جداول `users`(profiles) و`subscriptions` مع RLS + GRANTs.
- تسجيل/دخول/خروج، مسار محمي `/app`.
- هيكل التصميم (RTL، خط عربي، وضع داكن/فاتح).
- تسليم: مستخدم يسجل ويرى لوحة فارغة.

المرحلة 2 — الاستيعاب والتخزين
- جدول `episodes` + `jobs`، رفع مباشر إلى التخزين، أو إدخال رابط.
- استخراج المدة، فحص الحصة قبل القبول، حالة `queued`.
- شاشة قائمة الحلقات مع تحديث الحالة (polling كل 5 ثوانٍ).
- تسليم: رفع ملف يظهر كحلقة بحالة «في الانتظار».

المرحلة 3 — خط التفريغ
- عامل: تنزيل، تحويل ffmpeg، تقطيع 10 دقائق، STT لكل مقطع، دمج مع إزاحة زمنية.
- تنقيح LLM حسب اللهجة (ترقيم، إزالة حشو، توحيد الأسماء) مع الحفاظ على حدود المقاطع.
- كتابة `transcripts` + `transcript_segments`، حالة `ready`.
- إعادة المحاولة مع backoff، وحالة `failed` برسالة واضحة.
- تسليم: حلقة 30 دقيقة تُفرَّغ آلياً وتُعرض بمقاطعها.

المرحلة 4 — الترجمة والمحرر والتصدير
- ترجمة إنجليزية بدفعات من 20 مقطعاً مع حفظ الفهارس الزمنية.
- محرر مقاطع (تحرير، دمج، تقسيم، حفظ) لكل لغة.
- مولدات SRT/VTT/TXT (أحادي وثنائي اللغة) + تنزيل.
- تسليم: ملف SRT عربي وإنجليزي صالح يُشغّل في VLC/YouTube.

المرحلة 5 — الاشتراك والحصص
- Stripe Checkout + بوابة العميل + webhook على `/api/public/stripe`.
- عدّاد دقائق شهري، منع الرفع عند التجاوز، صفحة ترقية.
- تسليم: ترقية فعلية تفتح الحد الأعلى.

المرحلة 6 — التلميع والإطلاق
- صفحة هبوط عربية + تسعير + SEO (عنوان/وصف/OG لكل صفحة).
- سياسة الخصوصية وحذف الصوت، تصدير/حذف الحساب.
- مراقبة: سجل أخطاء الوظائف، تنبيه عند فشل > 10%.
- فحص أمني، اختبار حمل بسيط، نشر.

## 4) نموذج البيانات

- `profiles`: id (=auth user), display_name, locale, created_at.
- `subscriptions`: id, user_id, plan (`free`|`pro`), status, stripe_customer_id, stripe_subscription_id, current_period_start/end, minutes_quota, minutes_used.
- `episodes`: id, user_id, title, source_type (`upload`|`url`), source_url, storage_path, duration_seconds, dialect (`msa`|`gulf`|`egyptian`|`levantine`|`maghrebi`), status (`queued`|`processing`|`ready`|`failed`), error_message, created_at.
- `transcripts`: id, episode_id, language (`ar`), model, raw_text, refined_text, created_at.
- `transcript_segments`: id, transcript_id, idx, start_ms, end_ms, text.
- `translations`: id, transcript_id, target_language (`en`), status, model, created_at.
- `translation_segments`: id, translation_id, segment_idx, text.
- `jobs`: id, episode_id, kind (`transcribe`|`translate`), state, attempts, locked_at, last_error.

قواعد: RLS على كل جدول بحيث يرى المستخدم صفوفه فقط؛ GRANTs صريحة لـ authenticated و service_role؛ الوصول الإداري/العامل عبر مفتاح خدمة فقط.

## 5) نقاط API الرئيسية

- `POST /episodes` — إنشاء حلقة من رفع أو رابط (يتحقق من الحصة).
- `POST /episodes/upload-url` — رابط رفع موقّع.
- `GET /episodes` / `GET /episodes/:id` — قائمة وتفاصيل مع الحالة.
- `DELETE /episodes/:id` — حذف الحلقة وصوتها.
- `POST /episodes/:id/retry` — إعادة تشغيل وظيفة فاشلة.
- `GET /episodes/:id/transcript?lang=ar|en` — المقاطع.
- `PATCH /segments/:id` — تعديل نص مقطع.
- `POST /episodes/:id/translate` — بدء الترجمة.
- `GET /episodes/:id/export?format=srt|vtt|txt&lang=ar|en|both` — تنزيل.
- `GET /me/usage` — الخطة والدقائق.
- `POST /billing/checkout` و`POST /billing/portal`.
- `POST /api/public/stripe` — webhook (تحقق توقيع).
- `POST /api/public/worker/tick` — تشغيل العامل (سر مشترك في الترويسة).

## 6) استراتيجية الاختبار (TDD)

اكتب الاختبار قبل الكود في كل مهمة:
- وحدات نقية أولاً: مولد SRT/VTT (تنسيق الوقت، الفواصل، RTL)، تقطيع الصوت وإزاحة الطوابع، حساب الحصة، تجميع دفعات الترجمة. هذه تغطي أخطر منطق ولا تحتاج شبكة.
- تكامل: إنشاء حلقة → وظيفة → نتيجة، مع مزودات ذكاء ومخزن وهميين (fixtures ثابتة لصوت 30 ثانية).
- سياسات الوصول: اختبار أن مستخدم «ب» لا يقرأ حلقات «أ».
- الفوترة: أحداث webhook مسجّلة (checkout.completed, subscription.updated, invoice.failed) تُطبَّق بشكل idempotent.
- E2E (Playwright): تسجيل → رفع ملف قصير → انتظار الجهوزية → تصدير SRT → التحقق من المحتوى.
- بوابة الجودة: أي خطأ من بوابة الذكاء (400/402/429) يجب أن يظهر للمستخدم برسالة صريحة، مع اختبار لكل حالة.

## 7) المخاطر التقنية والتخفيف

| الخطر | التخفيف |
| --- | --- |
| دقة ضعيفة على اللهجات | تلميح لهجة في الـ prompt + مرحلة تنقيح LLM + معجم مصطلحات لكل مستخدم لاحقاً؛ قياس WER على 5 عينات حقيقية قبل الإطلاق |
| ملفات طويلة تتجاوز حدود النموذج | تقطيع إلزامي 10 دقائق مع تداخل 2 ثانية ودمج بإزاحة؛ ممنوع قص الصوت |
| مهلة تنفيذ الوظائف الخادمية | معالجة مقطع واحد لكل استدعاء + جدول `jobs` يستأنف من آخر مقطع |
| تكلفة الذكاء تتجاوز الاشتراك | تسعير مبني على الدقائق، حد صارم قبل البدء، تسجيل تكلفة كل وظيفة |
| فشل/حدود المزود (429/402) | backoff مع Retry-After، إيقاف الطابور عند 402/403 وإظهار السبب، لا إعادة محاولة للأخطاء النهائية |
| انحراف الطوابع الزمنية في الترجمة | الترجمة مقطعاً بمقطع مع فهرس ثابت وتحقق من تطابق العدد؛ فشل الدفعة يعيد المحاولة بدل الدمج |
| ffmpeg/معالجة الصوت في بيئة الحافة | تحويل داخل العامل فقط؛ إن تعذر، استخدام خدمة تحويل خارجية أو WAV/MP3 مباشرة |
| خصوصية المحتوى | تشفير في التخزين، حذف الصوت بعد 7 أيام، زر حذف فوري، عدم استخدام المحتوى للتدريب |
| RSS/روابط غير موثوقة | قائمة سماح للمخططات، حد حجم، مهلة تنزيل، منع الشبكات الداخلية (SSRF) |
